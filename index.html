Blast radius is not a reachability problem

A scanner can tell you which services contain a patched image. That set is not the answer. Two services running the identical image can see a 40 ms regression and a 1 ms regression, because one sits at 90% utilisation behind a fan-out and the other does not.

The cost of a change is set by where it lands in the queue, not by how many places it lands.

Move the slider above and nothing about the patch changes — only the traffic does. Four of the twelve services carry the new image; the rest inherit the damage through call paths and shared dependencies. Checkout never runs the patched image at all.

How it works

  1. Measure the change in isolation.

    Differential profiling of the old and new image attributes the regression to specific code paths — TLS handshake, compression, syscall overhead — instead of one aggregate number.

  2. Convert it per service.

    Each service invokes those paths at a different rate. A TLS-terminating gateway inherits most of the cost; a static file server inherits almost none.

  3. Amplify by local queueing.

    A service-time increase raises utilisation, and waiting time grows with it non-linearly. This is the step that separates a harmless patch from an outage.

  4. Propagate through the graph.

    Costs compose along call paths, take the worst case across parallel fan-out, and accumulate at shared dependencies. Retry loops are solved as a fixed point, which is what surfaces changes that cascade rather than settle.

Where it is today

The model is built and validated against discrete-event simulation. It identifies the affected set exactly, predicts impact within roughly 5% up to 93% utilisation, and proves saturation cases arithmetically rather than statistically. Against a model that ignores queueing it is seven times more accurate at normal load and twenty times more accurate near saturation.

Next is calibration against live telemetry — OpenTelemetry traces for topology, arrival rates and service times — and validation against injected latency in real clusters.
